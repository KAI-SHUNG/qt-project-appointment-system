# 医院专家门诊预约管理系统课程设计报告

> 题目：题目 2——医院专家门诊预约管理系统  
> 开发环境：Qt 6 / C++17 / MinGW  
> 说明：文中标有“**[AI 辅助]**”的内容，表示在需求梳理、文字组织或代码检查阶段使用了 AI 辅助；程序的功能描述以项目当前源码为准。

## 一、任务分析

本题要求用 Qt 开发一个医院专家门诊预约管理系统，对专家、排班和患者预约进行统一管理，并能将数据保存到磁盘。核心不是简单录入信息，而是保证预约数据在新增、修改、删除和重新加载后仍然正确。

据此，我将任务分为四部分：

1. 建立专家、患者、时段、预约和医院五个领域对象，明确它们之间的关系；
2. 实现专家维护、排班维护、预约挂号、预约查询和退号等业务；
3. 在业务层统一校验重复编号、排班冲突、余号、身份证重复预约等规则；
4. 用二进制数据文件保存专家和预约信息，并在启动时自动加载、变更后自动保存。

其中，`Hospital` 负责保存全部医生和预约集合，`Doctor` 保存个人排班，`Appointment` 同时关联医生、患者、日期和时段。这样的组织方式能避免界面代码直接处理数据规则。

## 二、设计思路与软件功能

### 1. 总体设计

程序采用“数据模型 + Qt 图形界面”的分层思路。`src/` 目录放置独立于界面的数据模型；`ui/` 目录放置主窗口、页面和对话框；`test/` 目录放置控制台断言测试。主窗口使用左侧导航和 `QStackedWidget` 切换页面，启动后先读取本地数据，再创建各个页面。

```text
MainWindow
├── 首页概览 DashboardPage：统计数据、近期预约、科室分布
├── 预约挂号 RegisterPage：选择医生/日期/时段，填写患者信息
├── 预约查询 AppointmentsPage：筛选、查看详情、修改、退号
└── 医生管理 DoctorsPage：新增、编辑、删除医生和维护排班

数据层：Hospital ── Doctor ── Timeslot
                  └─ Appointment ── Patient
```

### 2. 功能模块

| 模块 | 主要功能 |
|---|---|
| 首页概览 | 显示专家数、预约总数、当日预约数、当日剩余号源，并列出近期预约和科室统计。 |
| 医生管理 | 新增、编辑、按姓名/编号/科室检索、删除专家；删除专家时级联删除其预约；可维护出诊时段。 |
| 预约挂号 | 按医生和日期显示可预约时段及余号；填写患者资料后生成预约号并提交。 |
| 预约查询 | 按医生、关键字、是否包含已完成预约筛选；可查看详情、修改未完成预约和退号。 |
| 数据管理 | 启动自动加载，增删改后自动保存；支持从一对 `.dat` 文件导入和向文件夹导出。 |

界面采用 `QListWidget`、`QTableWidget`、`QCalendarWidget`、`QComboBox`、`QLineEdit`、`QDialog` 等标准控件，信号与槽用于页面跳转、筛选、提交和刷新。全局样式集中在 `resources/style.qss`，使按钮、输入框和表格保持一致。

### 2. 主窗口与页面之间的协作

`MainWindow::buildPages()` 按“首页概览、预约挂号、预约查询、医生管理”的顺序创建页面，并加入 `QStackedWidget`。`onNavChanged()` 响应左侧 `QListWidget` 的当前行变化，切换当前页面后通过 Qt 元对象机制调用其 `refresh()`，避免页面显示旧数据。

首页中的 `navigateRequested(int)` 信号可使“去挂号”“查看预约”“管理医生”等按钮直接切换至对应页面。医生管理页的 `requestRegisterAppointment(doctorId)` 信号会跳转到预约挂号页，并调用 `RegisterPage::selectDoctor()` 自动选中目标医生。这个流程减少了用户重新选择医生的步骤。

导入时 `importData()` 让用户依次选择医生文件和预约文件，确认后调用 `Hospital::importData()`；导出时 `exportData()` 选择目标文件夹，若文件已存在会先提示覆盖。成功后 `refreshPages()` 刷新所有页面。**[AI 辅助]**：协助检查了页面跳转索引与刷新时机，避免页面间数据不同步。

### 3. 首页概览 `DashboardPage` 的实现

`refresh()` 是首页的总入口，依次调用三个私有函数。

| 函数 | 实现内容 |
|---|---|
| `refreshStatistics()` | 遍历全部预约，统计日期等于 `QDate::currentDate()` 的当日预约数；再遍历每位医生当天的排班，用“时段容量－已预约数”计算余号，并更新四张统计卡片。 |
| `refreshUpcomingAppointments()` | 筛选日期不早于当天的预约，按日期和开始时间排序，显示近期预约；双击某行可跳转到预约查询页。 |
| `refreshDepartments()` | 以科室名为键累计专家人数，填入科室统计表，便于快速了解各科室配置。 |

首页只读取 `Hospital` 中的数据，不直接修改数据，因此每次返回首页调用 `refresh()` 就能反映其他页面的操作结果。

### 4. 预约挂号页 `RegisterPage` 的实现

页面构造时连接医生下拉框、日期日历、时段列表和提交按钮的信号。`fillDoctors()` 将 `Hospital::getDoctors()` 中的专家写入下拉框；`selectDoctor()` 供医生管理页调用，优先选中传入的编号。

用户选择医生后，`onDoctorChanged()` 调用 `updateDoctorCard()` 显示姓名、科室、职称等资料，再调用 `refreshSlots()`。后者根据日历日期的星期过滤排班，用 `Hospital::countAppointments()` 计算每个时段的余号：已开始或无余号的列表项被设置为不可选；余号不多于 2 个时用醒目颜色提示。`updateSubmitState()` 确保已选择医生和有效时段时才启用“提交预约”按钮。

`submitAppointment()` 是挂号流程的核心，依次完成以下工作：

1. 读取并检查姓名、身份证号、手机号、症状和已选时段；身份证号使用 `^[0-9]{17}[0-9X]$`，手机号使用 `^1\d{10}$` 校验；
2. 调用 `nextAppointmentId(date)` 生成当日的空闲预约号；
3. 再次检查预约时段是否已开始，并弹出确认框；
4. 创建 `Patient`、`Appointment` 对象，调用 `Hospital::addAppointment()` 执行最终业务校验；
5. 通过 `persistHospital()` 保存。若保存失败，则调用 `removeAppointment()` 撤销刚添加的记录；保存成功后清空表单、刷新余号，并显示预约号。

这种“界面预检查 + 数据层最终检查”的双层方式既让用户及时得到提示，也防止其他入口绕过规则。

### 5. 预约查询页 `AppointmentsPage` 的实现

`fillDoctors()` 填充医生筛选下拉框，`resetFilters()` 将医生设为“全部医生”、清空关键字并关闭“包含已完成预约”。`populateTable()` 是查询页的核心：先按照医生、关键字、完成状态筛选，再按照预约日期、开始时间、医生姓名、预约号排序。关键字可匹配预约号、患者姓名或身份证号。

每行由 `addRowActions()` 加入“详情”按钮；未结束预约还会有“退号”按钮。`showDetails()` 打开 `AppointmentDialog`，若用户修改了日期、时段或症状，则暂存旧值、更新对象、必要时更换预约号，保存失败时恢复旧值。`cancelAppointment()` 只允许未结束预约退号，二次确认后删除记录并保存；若保存失败则重新加载磁盘文件，避免内存状态和文件状态不一致。

`resizeEvent()` 在页面大小变化后使用定时器调用 `adjustColumnWidths()`，让表格数据列随窗口宽度调整，避免界面缩放时显示拥挤。

### 6. 医生管理页 `DoctorsPage` 的实现

`fillDeptFilter()` 合并预定义科室与当前数据中实际出现的科室，构造科室下拉筛选项。`populateTable()` 按科室和关键字筛选医生，显示编号、姓名、性别、年龄、职称、科室和排班数量；`scheduleText()` 将排班转换为“星期 + 起止时间 + 容量”的提示文本。

页面功能由以下函数实现：

| 函数 | 实现内容 |
|---|---|
| `onAdd()` | 打开 `DoctorDialog`，调用 `nextFreeDoctorId()` 预填首个未使用的 `D001`—`D9999` 编号；确认后调用 `Hospital::addDoctor()` 并保存。 |
| `editDoctor()` | 用 `setDoctor()` 预填表单，确认后更新姓名、年龄、性别、职称和科室，编号保持不变，再保存。 |
| `deleteDoctor()` | 提示“删除会同时删除该医生预约”；确认后调用 `Hospital::removeDoctor()` 完成级联删除并保存。 |
| `scheduleDoctor()` | 打开 `TimeslotDialog`，在对话框中新增、删除或整体保存排班。时段冲突由 `Doctor::addTimeslot()` 判断。 |
| `registerWithDoctor()` | 发出 `requestRegisterAppointment(doctorId)`，跳转到挂号页并预选此专家。 |

`onSearch()`、`onReset()` 和 `refresh()` 分别负责执行筛选、清空筛选和重新装载表格；`adjustColumnWidths()` 与预约查询页相同，用于自适应表格列宽。

### 7. 数据对象与排班

`Human` 是人员基类，保存姓名、年龄和性别；`Patient` 在此基础上增加身份证号和联系电话；`Doctor` 增加编号、职称、科室及 `QList<Timeslot>` 排班。`Timeslot` 保存星期、开始时间、结束时间和容量，并在构造时拒绝结束时间不晚于开始时间、容量不大于 0 的非法数据。

医生新增时段时调用 `Doctor::isConflict()`。该函数只比较同一星期的时段，并使用区间重叠条件判断冲突：

```cpp
bool Timeslot::overlaps(const Timeslot& other) const
{
    if (dayOfWeek != other.dayOfWeek)
        return false;
    return startTime < other.endTime && other.startTime < endTime;
}
```

因此相邻时段如 09:00–10:00 和 10:00–11:00 可以并存，交叉时段则不能加入。**[AI 辅助]**：对时间区间边界条件和异常提示进行了检查与整理。

### 8. 专家与预约管理

`Hospital::addDoctor()` 按医生编号查重；`removeDoctor()` 删除专家后倒序遍历预约表，删除该医生的全部预约，实现级联删除。

预约新增集中在 `Hospital::addAppointment()`，而不是仅在界面中判断。其校验顺序为：医生是否存在、妇产科是否为女性患者、时段是否已经开始、预约号是否重复、同一身份证号是否在同一天同一时段重复预约、所选时段是否属于该医生排班、该时段是否已满。任一条件不满足均抛出 `std::invalid_argument`，界面捕获后用 `QMessageBox` 提示。

核心的满号判断如下：

```cpp
if (countAppointments(appointment.getDoctorId(), appointment.getDate(), timeslot)
    >= timeslot.getCapability()) {
    throw std::invalid_argument("该时段预约已满");
}
```

其中 `countAppointments()` 遍历预约集合，统计同一医生、日期和时段的预约数。预约号由 `nextAppointmentId()` 按 `AyyMMdd001` 的格式从小到大寻找空闲编号，例如 2026-09-07 的首个编号为 `A260907001`。

`RegisterPage::refreshSlots()` 根据所选日期过滤医生排班，并显示“剩余 N 个号”；已开始或已满的项目被禁用。`submitAppointment()` 对姓名、18 位身份证号、11 位手机号和症状描述进行格式校验，确认后构造 `Patient` 与 `Appointment` 并提交给 `Hospital`。

### 9. 查询、修改和退号

预约查询页从 `Hospital::getAppointments()` 读取数据，可按医生、预约号、患者姓名或身份证号筛选；默认不显示已结束预约。结果按日期、开始时间、医生姓名和预约号排序后填入 `QTableWidget`。

修改预约时，程序暂存旧日期、旧时段和旧症状；若日期改变，则重新生成预约号。保存失败会恢复旧数据。退号前检查预约是否已结束，并进行二次确认。**[AI 辅助]**：在梳理修改预约的回滚路径时，对“先保存旧值、失败后还原”的处理方式提供了建议，最终实现以代码为准。

### 10. 文件读写与导入导出

专家数据写入 `doctors.dat`，预约数据写入 `appointments.dat`。`Hospital::saveDoctors()` 和 `saveAppointments()` 使用 `QDataStream` 顺序写入字段，并使用 `QSaveFile` 的 `commit()` 提交，避免写入中断直接破坏旧文件。

加载时先读取专家、再读取预约；引用不存在医生的脏预约会跳过，避免异常数据造成程序崩溃。导入时先在临时 `Hospital` 对象中读取两份文件，读取成功后再替换当前内存数据并保存；导出则复制当前数据到用户选择的文件夹。**[AI 辅助]**：协助检查了文件读写的字段顺序、临时加载和失败恢复的风险点。

## 四、软件功能测试

### 1. 测试数据与方法

测试分为界面操作测试和数据层断言测试。数据层测试位于 `test/`，构建时设置 `BUILD_TESTS=1`，可执行以下命令：

```text
qmake 09025117.pro BUILD_TESTS=1
mingw32-make
```

测试使用临时目录和构造数据，不会修改正式数据文件。测试中的典型数据包括：心内科医生 `D201`（09:00–10:00，容量 1）、女性妇产科医生 `D203`、身份证号 `110101198501011111` 的患者，以及未来日期的预约。

| 测试项 | 操作与预期结果 |
|---|---|
| 医生编号 | 添加 `D001` 后再次添加同编号，抛出异常；可正确查询已有和不存在的医生。 |
| 级联删除 | 给 `D100` 建立预约后删除医生，其预约集合变为空。 |
| 排班与容量 | 不在排班内的时段被拒绝；容量为 1 的时段第二次预约被拒绝。 |
| 重复预约 | 同一身份证号在同一天、同一时段再次预约被拒绝；不同日期或不同时段允许。 |

| 文件往返 | 保存 1 位医生和 1 条预约后重新加载，核对编号、科室、排班、身份证号、日期和症状均一致。 |
| 导入导出 | 导入临时数据后导出，重新加载导出文件可查询到原医生和预约；再次导出可覆盖已有文件。 |

`testHospital()` 共汇总 9 组医院数据测试；此外还包含人员、患者、医生和时段对象测试。测试用 `assert` 判断预期结果，所有断言通过时程序正常结束并输出 Passed 信息。

## 五、内容总结与建议

通过本次设计，我对 Qt 的页面组织、信号与槽、对话框交互以及 `QDataStream` 文件读写有了较完整的实践。项目中较重要的一点是把预约规则放到 `Hospital` 数据层处理：无论未来从哪个页面调用，只要经过同一接口，就不会绕开容量、排班和重复预约等限制。

目前系统已经满足题目要求的专家管理、预约管理、查询显示和文件读写等功能。后续可继续改进：一是为数据文件增加版本号和校验，便于兼容后续字段变化；二是把 `QTableWidget` 更换为 Model/View 架构，适应更多数据；三是增加预约修改时的完整重复与容量复核，并加入更多界面自动化测试；四是对身份证号、电话等敏感信息在展示时做脱敏处理。
